# GoDrop manual QA fixes — 4 November 2026

The changes keep the existing page layouts and colours. They do not change historical orders, prices, payments, refunds, earnings, or wallet balances.

| # | Status | Cause and change | Main files |
|---|---|---|---|
| 1 | Fixed | The shipment query embedded payments without choosing between two production foreign keys. Both list views and order details now select the primary delivery payment relation explicitly. The home card used to filter out delivered and cancelled orders; it now uses the latest owned delivery and links completed orders to History. The live owner-policy check returned one history shipment, zero active shipments, and a visible payment for the reported order. | CustomerShipments.tsx, shipment-query.ts, customer-home-data.ts, CustomerHome.tsx |
| 2 | Partially | The selected size drives the review label, illustration, quote and checkout payload. Changing size or addresses immediately makes the previous quote unusable. The reported Medium-to-Small label change did not reproduce in source: both steps already used the same size state. The review now shows the driving distance. Live rates are £4.49 for the first 2 miles plus £1.20 per extra mile; the live surge master switch is off and configured size/weather fees are zero. £146.13 is consistent with about 120.033 miles, before any discount. The original route distance and quote were not available, so the exact historic quote cannot be confirmed from the two address strings. | NewDeliveryModal.tsx, DeliverySteps.module.css |
| 3 | Fixed | The £100 displayed while settings loaded was a hardcoded fallback. The UI now waits for the admin limit (currently £50). Item input stays in the editor until Save, price stays as text while typing, and the quantity label no longer wraps two buttons. Saved estimates display per-item price times quantity. An estimate is optional; no store price is invented. | ShoppingBookingForm.tsx, ShoppingItemEditor.tsx |
| 4 | Fixed | Timers did not cancel in-flight autocomplete and place requests. Both forms now wait 220 ms, cancel obsolete work and ignore stale responses. The proxy forwards the request cancellation signal to the maps provider. Provider latency and typing on the signed-in browser were not timed. | NewDeliveryModal.tsx, ShoppingAddressField.tsx, address-request.ts, google.ts, google-proxy.ts, Google autocomplete/place routes |
| 5 | Fixed | Header search had no form action, and the old tracking route was a placeholder. The header and home now lead to /track. The lookup reads only shipment status. Unknown codes show “Shipment not found”; service errors show a retry message. Existing /track/:code links redirect to the working page. | track/page.tsx, track/[trackingNumber]/page.tsx, public-tracking.ts, Header.tsx, HomeSlides.tsx |
| 6 | Fixed | The reported text and Mirpur addresses are in the actual historical order row, not hardcoded by the tracking UI. Operations admins can flag or unflag completed/cancelled records on the order detail page. The flag uses the existing audit log and does not rewrite the order, hide it, or change payments.
